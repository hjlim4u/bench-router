# Bench-router handoff

Use this skill only for a task the caller wants to hand off. The router validates the selected profile, owns dispatch receipts, and collects results. The caller still verifies the work and records feedback.

## Setup

- Install globally or into any project with `npx skills add hjlim4u/bench-router -g` (or `npx skills add /path/to/bench-router`).
- Run `scripts/cli.py` with Python 3.11+ from this skill's installed path. It works standalone from a copied or linked skill directory in any working directory.
- Use the same runtime user's default config (`~/.config/bench-router`) and cache (`~/.cache/bench-router`) across agents, unless the operator has deliberately set shared `XDG_CONFIG_HOME` and `XDG_CACHE_HOME`. Keep all agents sharing a cache on one OS runtime; native Windows and WSL use different lock implementations and must not concurrently point at the same physical cache. Do not create agent-specific caches or copy snapshots.
- `profiles.toml`, Herdr, herdr-projects 1.2.1 and the target agent CLI must already be configured for live dispatch on Linux/WSL2. The task `cwd` must be the top level of a git repository with a commit. Profile `args` may only carry a model (`--model`/`-m`) and an effort; agent permissions follow the board's `worker.access` setting. See [Projects setup](../../docs/projects.md). Run `python scripts/cli.py status` to inspect snapshot health. See the [reference](../../docs/reference.md) for setup and command contracts.

## Delegate and recover

Use the [vendor-guided decision workflow](references/decision.md) for semantic facets and final profile selection: Jev when `TYPESAFE_API_KEY` (or `JEV_API_KEY`) is set, otherwise the host's native `bench-decider` (Antigravity Flash, Codex GPT-6 Luna, Claude Code Haiku). Pass the current host through `scripts/decide.py --host antigravity|codex|claude`; `BENCH_ROUTER_DECISION_MODEL` overrides its model. Read that reference before choosing; the helper implements provider detection and response validation. Do not send these decisions through Router delegation or recursively invoke this Skill.

1. Create a temporary UTF-8 JSON task file with `schema_version: "1.0"`, a unique `task_id` (UUID hex is suitable), `round: 1`, `summary`, `prompt`, and an existing, trusted absolute `cwd`. Add only relevant optional task fields. Keep the task content and `(task_id, round)` stable for retries; use a new round only after checking the previous run's effects. Remove the temporary file once its CLI output is captured.
   Supply explicit `facets` (`{axis: [value]}`) only from `python scripts/cli.py wiki facets`. The router batches unresolved semantic facets and workload analysis in its first stage; do not run a duplicate facet pass. It then judges exact model/effort suitability without benchmark scores, retrieves relevant evaluations for remaining candidates, and compares compatible raw observations in code. Conflicting benchmarks need an optional relevance judgment without candidate scores. Unknown facets fail with the allowed list.
2. Run `python scripts/cli.py route --task TASK_FILE --host HOST --dry-run` to obtain the current stage packet. Follow the reference, save `{"stages": [<decision.completed entries>, <current response>]}`, and repeat `--decision-response RESPONSE_FILE --dry-run` until selected. Execute with the same response and without `--dry-run`, or pass the resulting 3.0 `selection` record using `--selection SELECTION_FILE`. A live `route --host HOST` can call configured Jev directly; when native handoff is needed it returns `decision_required` without dispatch. Pass global options such as `--herdr-session` before `route` when needed. Read the JSON `status` even when the process exits nonzero, and retain `run_id` and `cwd` for recovery. Add `--dry-run` to validate selection without dispatch. Plain `route` defaults to `vendor-guided`; use `--policy legacy` only when the caller explicitly requests the old automatic policy. `decision_required` and `decision_unavailable` use exit 17. Never silently switch policies.
3. For `blocked`, address the reported approval or question through the normal caller workflow. For `timed_out` or `delivery_uncertain`, run `collect --run-id RUN_ID --cwd CWD --wait-ms N`; never generate a fresh task ID or resend the prompt to resolve uncertainty. For `conflict`, inspect the warning and existing receipt before another dispatch. A completed result means the artifact contract passed, not that the task succeeded.
4. A `completed` run's agent panes are closed automatically so finished agents stop holding resources (`release` in the output; agents still working or blocked are left open). To continue that agent's conversation, run `python scripts/cli.py resume --run-id RUN_ID --cwd CWD`; it reopens the board task's space and restarts the agent in the same session without sending anything.
5. Inspect the returned result and verify the requested work. Record the verified outcome with `feedback --run-id RUN_ID --cwd CWD --outcome success|partial|fail` when there is a run to assess.

## Parallel handoff

Default to `route`. Use `parallel` only when independent subtasks or a comparison of approaches is worth the cost: it starts tasks × fanout agents.

For several subtasks or a best-of-N attempt, write a group file (`group_id`, git top-level `cwd`, `tasks` without `cwd`, optional `fanout`, `max_parallel`, `isolation`) and run `python scripts/cli.py parallel --group GROUP_FILE` (`--dry-run` to preview profiles). Each agent works in its own git worktree. The default policy selects every fanout member through the same guidance procedure. `--decision-response` accepts an object keyed by member label (for example `t1-1`); resolve pending choices and rerun with all previous replies until the complete plan validates. No worktrees or workers are created while any choice is pending. A saved live group plan freezes selections for recovery. Choose `isolation`: `isolated` (no sharing) or `shared` (agents share notes and intermediate results in a scratchpad). Review rounds and voting are the orchestrator's job. Rerun the same group file to recover; it never resends prompts. Each member's `worktree`/`branch` is where the board committed the agent's work; compare and merge those branches yourself, then remove the worktrees.

- Worktrees start from `HEAD`; uncommitted changes in `cwd` are not included (`dirty_base` warning).
- The main repository must already be trusted in each agent CLI; otherwise agents report `blocked` at startup. Worktrees under a trusted repository were not asked again.
- A member that was `blocked` before its prompt is not resent by rerunning the same group. Resolve the cause, then use a new `group_id` or `round`.

## Projects collaboration

Use ordinary `route` tasks for implementation, review and revision. Pass earlier artifacts explicitly in each new round. For blocked work use the returned board task ID (`thread_id`, e.g. `repo/12`) with `herdr-projects details`, and answer it on the board through the caller's normal approval workflow. Never delegate, retry or tell the task directly to recover a Router submission. To steer a live run, send one explicit message with `python scripts/cli.py tell --cwd CWD [--run-id RUN] --message TEXT` (for a parallel member, `--cwd` is its router worktree `<cwd>/.bench-router/worktrees/<group_id>/<label>`); it is logged in `runs/RUN/messages.jsonl`, and a settled run needs `resume` first. Pass `--wait-ms 0` to `route`/`parallel` to get run IDs right after submission, then compose patterns (relay, broadcast, best-of-N, review rounds) yourself; the router implements none. Two control utilities help: `python scripts/cli.py collect --run CWD RUN_ID --run … --until any|all --wait-ms N` waits for the first or all runs, and `python scripts/cli.py stop --cwd CWD [--run-id RUN]` stops a live run (it then collects as `execution_failed`). For a parallel member, CWD is its router worktree. A task with `"execution": "headless"` runs a one-shot CLI (`claude -p`, `codex exec`, `agy -p`) with approvals off in its own herdr worktree pane, shown on the board without an agent; it takes no `tell`. All Router executions share durable task binding, the four-active limit and the overlapping-workspace guard. Verify results and record `coordination feedback` separately; do not delegate recursively. Shared scratchpads sit outside each agent's worktree; with `worker.access ask` every write there needs approval.

## Shared data

Routing reads the shared snapshot; it does not refresh it. One user-level scheduled `refresh` can keep data current. Run `python scripts/cli.py refresh` manually only when explicitly requested or operating the shared schedule. Concurrent refreshes and dispatches to the same `cwd` return a busy/conflict result; do not work around their locks. See `status` and the JSON warnings for stale or missing evidence.
